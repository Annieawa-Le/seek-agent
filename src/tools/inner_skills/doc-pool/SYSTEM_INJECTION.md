# doc_pool — 文件池

Manager 模式编排工具：把子模型「读阶段」读取的文件片段沉淀为命名文件池，供后续委派的员工共享背景文件。

## 何时使用

- 多个子模型需要理解同一批文件（如渲染组共享样式/组件文件、后端组共享接口定义）
- 想复用某个子模型调研过的文件内容，避免新员工重复读

## 用法

1. **关联**：`doc_pool{pool_name: "渲染组", name: "渲染修复员"}` —— 建立关联后，
   该子模型循环中「读阶段」的读取会自动记录进池；被修改过的文件片段自动移除。
2. **委派注入**：`agent_task{name: "新员工", task: "...", pool_name: "渲染组"}` ——
   新员工初始对话会带上池中的文件片段作为参考上下文。

## 读阶段语义

从子模型第一条工具调用起，从前往后扫描，直到第一个**写入工具**
（add_patch / del_patch / modify_patch / create_file / replace_file / wrap_by 等）
或 **TODO 工具**（create_todo 等）为止——之前的读取工具
（read_file / read_lines / scan_file 等）都视为读阶段，被记录。
